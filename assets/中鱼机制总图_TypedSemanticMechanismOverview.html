中鱼机制总图｜Typed Semantic Mechanism Overview

这不是“一堆系数相乘”的系统，而是一套： 参数 → 语义解析 → Domain 输出 → 跨域组合 → 玩法修正 → 最终决议 的类型化机制架构。

一句话总览： 各 Domain 内部可以复杂，但跨 Domain 边界必须很薄： Spatial 输出 L（Native Supply）， Interaction 输出 C（captureRetention）， Opportunity 输出 μT / LogicalOpportunity， Candidate 层只做 q = L × C，再按 μT 做 Reduce。

一、六层主链

L0 Authoring / Facts / Parameters
鱼参数、世界事实、玩家输入、持久状态、内容元数据
↓
L1 Domain Semantic Resolvers
把参数变成有语义的中间量：ThermalRelation / TargetRelation / TaskAffordance / BehavioralContext
↓
L2 Domain Products
Spatial → L；Interaction → C；Opportunity → μT / LogicalOpportunity
↓
L3 Candidate Assembly
same-support Join：q = L × C；然后按 μT 做 Reduce 得到 W
↓
L4 Gameplay Policy
EligibilityTransform / MassTransform / Redistribution / ResolutionCondition
↓
L5 Resolution / Commit
Normalize Late → authoritative selection / roll / commit

二、三大核心 Domain 输出

Spatial

B + P + EnvironmentResolver → L
  • B：Reference Species Intensity
  • P：optional World Supply
  • L：Local Native Supply

Interaction

Presentation + Resolver → C
  • 先做 Perception / Interpretation
  • 再结合 Value / Affordance
  • C：captureRetention

Opportunity

Formation → LogicalOpportunity + μT
  • WHEN 和 WHO 分离
  • μT 是 evaluation measure
  • 不是 fish weight

三、Candidate Assembly 的唯一主干

q = L × C
W = Reduce(q, μT)
  • L：Native Supply
  • C：captureRetention
  • μT：Opportunity Evaluation Measure
  • W：Native Candidate Mass

Candidate 层不再重读 Temperature / Structure / Bait / Activity 等 raw cause。

四、五个关键机制

1. 温度（Temperature）

  • 输入：preferredMin / preferredMax / toleranceMin / toleranceMax
  • 先形成 ThermalRelation
  • 再分别进入 Spatial / Functional / Readiness
不是 TemperatureCoeff，而是“一套共享 biological trait，多处 role-specific interpretation”。

2. 结构体（Structure）

  • 默认 author：Optimal / Secondary / Marginal / Unsuitable
  • 允许少量 Context Override（如 strong flow）
  • 输出：Resolved Structure Relation → Environment Response
不是 StructureCoeff × FlowCoeff。

3. 功能能力（Functional）

  • 鱼侧：Capacity
  • 玩法侧：TaskDemand
  • Compare：Capacity vs Demand → TaskAffordance
表达“想吃但追不上”，而不是一排能力系数相乘。

4. 饵 / Presentation

  • Source → Propagation → Receiver Signal
  • Perceptual Evidence → Target Interpretation
  • Value + Risk + Affordance → captureRetention
不是 BaitCoeff / MotionCoeff / PoseCoeff 的平铺结构。

5. Groundbait / 打窝

  • Immediate Cue → 当前 C
  • Aggregation State → 未来 L
  • Consumption / Satiation → 未来 Readiness
  • Learning / Association → 未来 Interpretation
必须拆成多条因果路径，不能用一个 GroundbaitCoeff 代表。

6. Gameplay Policy

  • 活动、教程、保底、推荐、限制
  • 都放在 Native Candidate 之后
  • 显式声明是玩法 shaping，不伪装成自然规律
Policy 不改写 Native truth。

五、最重要的几条纪律

不要再做的事

  • 不要继续发明平级 XxxCoeff
  • 不要把多个 Cause 压成一个匿名 FinalCoeff
  • 不要在 Candidate 层重算上游因果
  • 不要把 Unknown 当 0

应该坚持的事

  • 先定 causal topology，再定数学
  • Domain 内可以复杂，跨 Domain 边界要薄
  • Normalize Late
  • Shared Trait → role-specific interpretation
建议作为“机制速览页”插入 Notion 顶部，先给人一眼看懂全局，再往下钻 Concrete Spec。
